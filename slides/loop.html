02 · WORKFLOW AS SKILLS

My process lives in skills, not in my head

Skills say when. Scripts, lints and tests say whether.

Fired in the last 2 weeks: scenario-test 481× · verify 372× · spec 16×

Yellow = gates nobody skips: my approval before agents fan out, verify before any “done”.

Everything else is à la carte. A typo fix jumps straight to implement.

Second: my workflow is a loop of skills. A skill is just a Markdown file the agent loads when its trigger matches. Spec, tickets, implement, verify, ship, then babysit the PR until it’s merged. The numbers are real, from my Claude Code sessions in the last two weeks: the testing and verify skills fire hundreds of times, spec 16 times. A skill only says when to do something. Whether the work is right is decided by scripts, lints and tests the agent runs itself. I don’t run the whole loop every time. But the two yellow gates never get skipped: my approval before agents start building, and verify before anyone says done.
